# 市场与模型配置按目标形态参数化，桌面档不再只在桌面 tab 里管

原边界规定桌面档的插件与配置只在「插件 → 桌面应用」tab 里管，市场与模型页只服务 web 档，理由是「照搬一套 UI 会是第二份实现」。这条边界保住了实现的单一，代价是能力不对称：桌面档的插件只能手输 spec 安装，看不到目录，模型配置只能改原始 JSON 行。**决定把「目标形态」做成市场与模型页的参数**：UI、校验、交互只有一份，web 档写自己的 profile 落盘，desktop 档经桥接调用应用自己的 Plugin Manager / Config Editor（ADR 0011 的机制不变）。这一轮的范围是插件市场与模型配置（含模型导入）。远程访问、安装/修复/版本 pin、开机自启、授权插件都属于 web 档的进程与连接，对桌面档不适用。

**Considered Options**：

- **dsh CLI 的 `--profile desktop`** —— 不可行。CLI 解析 profile 名时就拒绝（`profile "desktop" is managed exclusively by the Electron application`），只读的 `list` 也一样（0.2.0-rc.2 实测）。绕过 CLI 直写 profile 已被 ADR 0011 否决。
- **在桌面 tab 内补齐市场与模型编辑** —— 拒绝。这正是原边界担心的第二份实现。
- **只加形态角标、安装仍只装 web** —— 拒绝。只解决了「看得见」，没有真正支持桌面档。
- **一份模型配置同时写入两档** —— 拒绝。两档共用凭据，但模型配置本来就互不相干（`profiles/` 分开）。强行同步会把两份独立的事实绑成一份。

**Consequences**：

- 桌面档的安装、卸载、启停与配置写入都要求桌面应用在运行、桥接已连接。条件不满足时，入口按桥接状态给出去向，不伪装成功，也不排队。
- 桌面档的安装事实只能在桥接连接时得知。拿不到时，形态角标如实显示「未知」，不缺省成「未安装」。
- web 档安装护栏里的 `--dump-config` 组合预检对桌面档物理不可执行。桌面档的组合校验由应用自己的 Plugin Manager 承担。
- 桌面应用 tab 收窄为 web 档没有对应物的部分：桥接状态与一次性安装引导、内置 bundle 及其插件行的开关、模型域之外配置行的原始 JSON 编辑。用户装的插件（连同它们带来的插件行）只在市场里出现一次，模型域那两行只在模型页编辑；原来 tab 里「粘包规格安装」的入口并入市场的自定义安装（多了一个「安装到」选择），不保留两个安装入口。
- 两档同一套 IPC 命令（安装/放行重装/移除/启停/更新检测带 `surface` 参数，在 Rust 侧分派一次），变更结果统一为一个「变更去向」类型，前端只有一个通知函数。首版为桌面档另开的平行命令与各自的结果类型已删除。
- 两档共用一道操作闸：同一时刻只跑一个插件操作（不分形态），卡片上每行的 busy 状态才不含糊。
