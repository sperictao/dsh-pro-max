# v0.3.6

修复宿主 Mac 开启代理后无法使用自身 Tailscale 远程地址的问题，并让 Launcher 只在浏览器真实可访问时报告远程就绪。

## Fixes

- **本机远程地址被 Shadowrocket 拦截**：远程检查现在区分服务端链路失败与本机 HTTPS 代理干扰；直连探针显式绕过代理，再结合 macOS 系统代理及绕过列表判断浏览器路径，不再把“服务可用但本机打不开”误报为远程就绪
- **修复建议指向错误的 DIRECT 规则**：宿主 Mac 改为显示并复制精确主机名，引导加入 Shadowrocket“通用 → 跳过代理（skip-proxy）”；内部 `DOMAIN,...,DIRECT` 仍保留给其他访问端设备，不再作为宿主 Mac 的修复方案
- **远程状态与打开动作过早**：只有 HTTPS、`/api/events.host` WebSocket、本地特权 API、授权插件和 Tailscale Serve 全部通过后，状态与时间轴才进入就绪；失败时禁用远程“打开”，并提供“复查并打开”入口
- **排障文档补齐代理路径**：明确区分宿主 Mac 的系统代理绕过与其他客户端的 DIRECT 规则，并记录 `scutil --proxy` / `ExceptionsList` 的验证方法

## 验证

- 本地与 Tailscale 远端首页均返回 200，`/api/events.host` WebSocket 均完成 101 握手；Tailscale Serve 继续直指 `127.0.0.1:3899`
