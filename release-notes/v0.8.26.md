# v0.8.26

本版修复自定义安装 GitHub 插件时构建脚本审批框不弹出的问题：pnpm 以 codeload tarball 拉取时打印的 allowBuilds 精确键是 URL 形态（不含 `git+`），旧解析器认不出，审批无法分流、只能手动改配置。另修复 scoped 包（`@scope/pkg`）启停开关写入非法 YAML 导致 web profile 启动即崩的事故级缺陷。业务配置格式与后端命令接口均未改变。

## Changes

- **codeload 键形态接入审批流**：`ERR_PNPM_GIT_DEP_PREPARE_NOT_ALLOWED` 失败输出中，pnpm 11 经 codeload tarball 拉取时打印的精确键是 `name@https://codeload.github.com/.../tar.gz/<sha>`（2026-09-21 Windows + pnpm 11.25 实测，此前实机样本是 `name@git+url#commit` 的 git 克隆形态）。`git_prepare_allow_keys` 判定从「含 git+」放宽为「含 git+ 或 ://」，两种形态都能提取并转审批对话框；`market_approve_builds` 的 IPC 键校验 `valid_allow_key` 同步接受 URL 形态（限长与可打印 ASCII 约束不变）。
- **自定义安装审批闭环回归测试**：自定义安装对话框的 approval 相位（被拦 → 审批框浮于其上 → 放行写 allowBuilds 重跑成功 / 拒绝回输入态）此前无测试覆盖，现补两条端到端路径用例（含 git 键原样回传不剥的断言）。
- **scoped 包启停开关 YAML 转义**：`@scope/pkg` 的 `@` 是 YAML 保留字符，启停覆盖行裸写包名会让 dsh 的 overlay 解析全灭、web profile 启动即崩（2026-09-20 事故）。落盘值现经 `yaml_scalar` 编码：白名单内裸词原样，其余双引号包裹转义；行级判定认得带引号形态（重复启停仍幂等、启用可删行）。

## 验证

- oxlint 0 错 0 警；Vitest 238 用例全绿（含新增 2 条自定义安装审批闭环）。

## 升级说明

- **无破坏性变更、无迁移**。已按手动指引改过 `pnpm-workspace.yaml` 的用户不受影响；allowBuilds 键是 commit 钉定的，仓库 HEAD 变动后重装会再次弹审批（新 sha 键），属 pnpm 固有语义。
