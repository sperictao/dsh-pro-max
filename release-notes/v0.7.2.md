# v0.7.2

本版把「看起来成功了」和「真的可用」之间的缝隙补上：本地模式的 ready 不再只看端口绑定，而是以「loopback HTTP 应答 → 应答后稳定观察 → 进程存活」收口，插件树激活崩溃不再伪装成启动成功；插件市场开放自定义安装，精选目录之外的 npm 包与 GitHub 仓库按同一闸门与审计路径装入；设置页 dsh 版本卡把兼容事实前置到一眼可读，dist-tag 列表按发布时间新→旧排序。

## Changes

- **本地模式 ready 步探活验证**：本地时间线扩为 4 步（node → install → start → ready），ready 步两阶段判定——等待首次 loopback HTTP 应答，应答后进入稳定观察期，观察期内进程死亡或停止应答都判失败并把 dsh-web.log 的具体报错带进时间轴（ready 失败同样提供日志展开）。背景：dsh 先绑端口、插件树激活在其后，激活崩溃发生在服务已应答之后——此前 token 已打印、页面可访问、数秒后秒死的故障在界面上全绿无报错。无授权插件时裸 `/` 的 401/404 按健康应答接受（浏览器经 token URL 换 cookie 后才是 200）
- **市场自定义安装**：发现页新增「自定义安装」，支持 npm 包（`pkg`、`pkg@1.2.3`、`@scope/pkg@1.2.3`、`npm:` 前缀）与 GitHub 仓库——网页网址、`.git` 后缀、`/tree/<ref>` 链接、`git@` SSH、裸 `owner/repo` 一律归一为显式 `github:` 前缀，落盘 spec 与审计日志一眼可读；前端镜像 `valid_identifier` 校验做即时反馈（Rust 闸门仍是唯一事实来源），其余协议（git+https、gitlab 等）如实拒绝。与目录插件同一安装闸门、策略、审计与构建脚本审批路径
- **dsh 版本卡兼容事实前置**：已装版本行新增状态胶囊——「验证过的兼容栈」「高于验证过的兼容栈」「不兼容」（布尔值由 Rust 侧 `dsh_version_is_compatible` 计算，前端不做 semver 解析）；列表中命中验证栈版本的行加同款标记；初始加载不再显示假的「未安装」；检测失败升级为警告盒并就近提供重试
- **dist-tag 按发布时间排序**：版本列表按各 tag 指向版本的发布时间新→旧排列（npm 查询一次取 dist-tags + time 组合字段，仍是一次进程调用、同一 15s 超时）；时间戳真解析 RFC3339 后比较（毫秒位缺省时字典序会错序），registry 未给时间的版本垫底并保持原顺序
- **契约扩展**：`DshLatestInfo` 新增 `installedCompatible` / `installedAboveSupported`，ts-rs 绑定同步重生成
