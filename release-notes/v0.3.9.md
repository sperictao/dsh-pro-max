# v0.3.9

验证栈整体跟到 dsh `0.1.1-rc.2` 线,并加上版本闸门杜绝"混搭"与"跨线"两种让远程访问静默失效的路径。

## Fixes

- **远程访问失效的根因修复（版本混搭与宽松放行）**：此前兼容判定只看「实际版本 >= 插件栈下限」，npm semver 又让 `^0.1.0-rc.8` 名义上覆盖 `0.1.1`，结果上游把 dist-tag 滚到新版本线后，一键安装会把与插件栈不同线的 CLI 装上，本地与远程访问一起静默失效。现在版本闸门要求「不低于下限且同一 x.y.z 演进线」，跨线一律拒绝
- **安装策略改为固定版本**：`install_supported_dsh` 不再被动跟随 `@next` dist-tag（上游滚动不照顾本应用内置授权栈的兼容性），固定安装 `SUPPORTED_DSH_VERSION`；跟线升级由本仓库显式 bump 常量与插件 pin 完成
- **设置页逐版本安装加闸门**：`dsh_install_version` 拒绝不兼容版本并说明支持线；版本列表新增 `incompatible` 标记，不兼容行禁用安装按钮并标红提示，底部说明同步修正（旧文案声称「未验证版本可用于本地访问」，对跨线版本并不成立）
- **credentials 被新版 dsh 重写后的针对性诊断**：装过跨线 dsh（其会把 `~/.dsh/.credentials.yaml` 重写为不兼容格式）的机器回到锁定线时启动崩溃，现在时间轴直接给出「只保留 KEY: value 行」的修复指引，而不是通用的「看日志」
- **验证栈跟线 `0.1.1-rc.2`**：`SUPPORTED_DSH_VERSION` 从 `0.1.0-rc.6` 升到 `0.1.1-rc.2`（与插件栈对齐并升线），内置 `dsh-client-connection-authz` 更新到 `0.1.1-rc.2-authz.3` / `c2e0ec50b9b9`、`dsh-auth-tailscale` 更新到 `0.1.1-rc.2-auth.2` / `b49ed12c6be7`；auth-tailscale 的 dev 引用从私有仓库 git+https 拉取改为相邻 submodule `file:` 路径，消除本地与 CI 的凭据依赖

## 升级说明

- 升级后首次一键启动会把 dsh 升到 `0.1.1-rc.2` 并自动迁移 credentials 格式（新版 dsh 读取旧扁平格式后自行重写）。**该迁移是单向的**：之后不要再安装 `0.1.0` 线的 dsh，设置页版本列表中的跨线版本已被标记为不可安装
- 已在 `0.1.1` 线上的机器直接可用，无需手动步骤
