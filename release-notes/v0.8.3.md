# v0.8.3

本版修复 git 来源插件（`github:owner/repo` 形态）安装被 pnpm 构建拦截时只给手动提示、不走审批放行链路的缺口。

## Changes

- **git-hosted 插件构建拦截接入既有审批流**：pnpm 11 对 git-hosted 插件 prepare 脚本的拦截是硬失败（`ERR_PNPM_GIT_DEP_PREPARE_NOT_ALLOWED`），错误输出没有 `Ignored build scripts:` 行，安装判定解析不出被拦包名，只能落到「手动改 pnpm-workspace.yaml」的静态提示。现从失败输出提取 pnpm 打印的精确 `allowBuilds` 键（`name@git+url#commit` 完整形态，解析不依赖缩进），与 registry 插件同样转入构建脚本审批对话框——批准后自动写入 yaml 并重装，不再需要手动编辑；键解析不出的变形输出仍保留手动提示兜底
- **git 键的写入与校验适配**：pnpm 要求的完整 git 键含 `+`，原 IPC 键白名单必拒，现新增 `valid_allow_key`（包名形态或 git 键形态）统一校验；`allowBuilds` 保留完整键（pnpm 11+ 据此精确匹配 git 来源），双写的 `onlyBuiltDependencies`（pnpm 10 兼容键）剥为纯包名，两者与既有包名剥法收敛为同一实现；审批对话框列表允许长键折行，不再撑破布局

## 验证

- `cargo test`：164 项全部通过（1 项忽略；含 git 键解析、失败转审批、双键写入幂等、IPC 键校验等新用例）
- 前端 `vitest`：109 项全部通过
- 实机全链路（pnpm 11.25）：安装 git-hosted 插件硬失败复现 → 键提取 → 写入 `pnpm-workspace.yaml` → 重装成功且 prepare 构建产物正常生成

## 升级说明

- 无破坏性变更；此前因该问题安装失败的 git 来源插件，升级后从市场重装即可走审批放行，无需手动改任何配置文件
