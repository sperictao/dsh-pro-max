# v0.8.10

本版把「已装 dsh 版本要不要装回锁定版」的决策从布尔兼容判定拆成三态（`decide_pinned_dsh`）：用户装过比验证栈更新的版本（含跨线）后，一键启动、远程一键配置与开机自启不再把它悄悄降回锁定版，改为保留当前版本并如实披露授权插件可能失配。

## Changes

- **版本决策三态化**：新 `PinnedDshDecision`——`KeepCurrent`（同线且不低于锁定版，保留）、`KeepCrossLine`（跨线但高于下限，保留并在时间线披露「高于验证过的兼容栈，授权插件可能不兼容」）、`InstallPinned`（低于下限、解析失败或未安装，装回锁定版）。原 `dsh_version_is_compatible` 保留服务 detect/状态展示，不再驱动安装决策
- **三个调用方统一**：本地一键启动的 install 步骤、远程 8 步时间轴的 install 步骤、开机自启守卫（`dsh_set_autostart`）全部走 `decide_pinned_dsh`，消除「装了新版本一开自启就被悄悄降级」的分叉
- **与 v0.8.7 安装闸门放开闭环**：任何 dsh 版本可装，装完也不会被启动/自启链路悄悄装回；跨线保留后的插件失配风险由 v0.8.9 的启动前导出漂移预检披露、启动失败诊断兜底，三层各司其职

## 验证

- `cargo test`：171 项全部通过（含 `decide_pinned_dsh` 全决策空间 9 断言：同线更高/等于、跨线新高、低于下限、解析失败、未装）
- `cargo clippy -- -D warnings`、前端 `vitest` 121 项、`tsc`、`check:i18n`（473 key，新增跨线披露文案 zh+en）通过

## 升级说明

- **行为变化**：此前一键启动/自启会把「不兼容」的已装版本直接装回锁定版；本版起只有低于下限（或未装）才装回，跨线新版本保留。若远程授权因此失效，时间线的披露文案与 v0.8.9 的插件披露会给出原因
- 无迁移、无配置变更
