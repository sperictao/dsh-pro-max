# v0.8.2

本版修复两个相互关联的 web profile 启动预检问题（都源于 `cordis.patch.yml` 的启停写入路径），并收敛了上一版修复引入的重复分支。

## Changes

- **启用插件后 patch 层被删空不再破坏启动预检**：启停写入在「启用」路径删掉最后一条停用覆盖行后，层被删空且不补回 `[]` 占位行，落盘成纯注释文件——YAML 解析为 `null` 而非顶层数组，dsh loader 启动预检（`dump-config`/web 启动）从此必拒（此前的修复只覆盖了读方向的空层判定，写方向的逆操作漏了）。现于唯一写核出口做空层归一：结果为空层时归一回 dsh 官方脚手架形态（注释头 + `[]`），落盘永远可解析为顶层数组；卸载清理共用同一写核，自动受益
- **预检失败后的重试不再假报成功**：安装护栏在「无新增依赖」（重装、升级、预检失败后重试）时原本提前返回成功并跳过启动预检，把存量损坏假报成安装成功（上一版依赖已落盘、预检未再跑）。现启动预检无条件执行，无新增依赖时失败按无关失败如实报告、不动已装插件
- **安装护栏收敛为单点预检**：将上一版修复中复制进「无新增依赖」分支的预检处理与主预检块合二为一，`dump-config` 只执行一次；B5 入口撞车检测仅在新增依赖时有意义，改由 `Option` 显式承载，无新增依赖时自然跳过

## 验证

## 升级说明
