# v0.8.13

Provider Studio 稳定性与完整性增强版：在 v0.8.12 重构基础上补齐 Provider 认证语义、模型发现、连接测试、目录能力元数据、批量选择与大列表性能，并以完整 E2E 审计收口。

## Changes

- **Provider 发现与连接测试**：支持无需 API Key 的兼容端点；模型发现完整透传普通自定义 Headers，并过滤 Authorization / x-api-key / Cookie 等保留凭据头；新增独立 `Test connection`，走真实推理端点的小请求，不再把 `/models` 发现当作连通性测试
- **自动发现 + Cache/SWR**：Provider 编辑/新增时按连接指纹自动发现模型，600ms debounce、旧请求竞态保护、持久缓存与 stale-while-revalidate；刷新失败时保留可用缓存，不让网络波动清空候选列表
- **Readiness 对齐 DSH/pi-ai**：显式环境变量缺失仍 fail-closed；自定义无凭据保持 anonymous；内置 catalog route 未配置 `apiKeyEnv` 时允许由 DSH/pi-ai provider-native auth / 已存登录凭据接管，不再被 Launcher UI 错误阻止；Launcher 自己的 Test/Fetch 不冒充 DSH 内部凭据
- **内置模型继承**：`models=[]` 的内置 Provider 可直接从锁定版本的 pi-ai 目录选择默认模型，不把继承目录物化回 `settings.yaml`；显式 models 仍保持替换语义
- **能力元数据与 Reasoning 门禁**：models.dev 目录新增上下文、最大输出、推理档与 text/vision/pdf/tools/json 等能力投影；全局 Reasoning Effort 跟随当前默认模型能力，切换到不支持的模型时自动清理无效档位
- **PDF / Document 语义修正**：PDF 仅作为目录能力元数据展示，不伪装成当前 llm-pi-ai 不支持的原生 input modality；既有手写 custom input 保持原样，避免编辑时静默覆盖
- **模型选择语义修正**：搜索后的 Select All / Clear 只作用于当前匹配结果；Model ID 身份统一大小写不敏感但保留原始拼写；移除旧 50 条候选硬上限
- **大列表性能**：超过阈值的候选列表采用固定行高窗口化，DOM 只渲染视口附近节点，但搜索、Select All 与保存仍作用于完整候选集合
- **目录可观测性**：状态行区分 Local snapshot / models.dev，显示 Provider 数、模型数、更新时间与最近刷新错误；旧 snapshot 保持兼容并自动补齐新元数据
- **端到端回归**：浏览器级 E2E 覆盖 readiness、目录刷新、reasoning 即时保存、Test/Fetch 分离、自定义 Provider 自动发现、75 模型虚拟化、完整 Select All、Make default、两步删除与默认回退

## 升级说明

- 无配置迁移；现有 `settings.yaml` 保持兼容，未由 UI 管理的 provider/model extra 字段继续原样往返
- API Key 仍只保存环境变量名，不保存明文 secret
- 内置 Provider 无 `apiKeyEnv` 时是否可用取决于 DSH/pi-ai 的 provider-native auth / 已存登录凭据；Launcher 不会读取或暴露这些 secret
- PDF 能力当前是目录元数据，不代表 DSH 会把 PDF 作为 provider-native content block 发送
- Provider enabled、OAuth/authKind UI、subagent model flag 等未进入本版本范围
