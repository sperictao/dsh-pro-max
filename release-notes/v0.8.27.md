# v0.8.27

本版修复插件市场「已安装」页检查更新看不见本地路径安装插件最新版的问题：以 `file:` 路径安装的插件（本地 dev 安装）此前整卡脱离更新检测，既无版本号也不查上游，重装还会落到 registry 上并不存在的 `name@latest`。现在这类安装按其包自述的 `repository` 归一出 GitHub 上游仓库，与远端默认分支 manifest 比对；有更新时按该仓库重装，更新前在说明对话框如实披露安装源从本地路径切到仓库。业务配置格式与后端命令接口均未改变。

## Changes

- **本地路径安装接入更新检测**：`InstalledPlugin` 新增 `upstreamRepo`（上游仓库 `owner/repo`），与已装版本同源于一次读盘的 `InstalledFacts`：spec 认得 GitHub 形态（`github:owner/repo`、pnpm 规范化的 `git+https://github.com/...`）即以 spec 为准；其余协议形态（`file:`/`link:` 等）回退包自述的 `repository`（字符串与对象两形态，带 monorepo `directory` 的按根 manifest 版本不可比不采信）；两者皆无的如实不检——不猜，卡片也不显版本，不放大成「已是最新」。检测按上游查 `raw.githubusercontent.com/<owner>/<repo>/HEAD/package.json`，registry 形态仍查 `registry.npmjs.org/<name>/latest`，兼容门禁与 release-age 窗口各自沿用原通道。
- **更新/重装回到上游仓库**：`updateSpecifierFor` 改读已装记录的 `upstreamRepo`——本地路径安装有更新时按 `github:owner/repo` 重装（pnpm 重新解析默认分支 HEAD），不再落到 registry 上并不存在的 `name@latest`（`@dsh-external/dsh-auto-review-jev` 实测 404）。批量预热的 npm 候选、更新说明的仓库查询同源读这一个事实，前端不再从 spec 重复推导。
- **更新前披露来源切换**：落盘 spec 不是 GitHub 形态而更新目标是仓库时，更新说明对话框明示「本次更新将从 `github:owner/repo` 重装，不再使用本地路径」（中英双语）。
- **回归测试**：Rust 侧新增 repository 解析（字符串/对象、大小写、`.git` 后缀、`#fragment`、gitlab、缺 `url`、monorepo `directory`）与 `file:` 安装解析上游的断言；前端新增本地路径安装的已装卡（版本号 + 已是最新 + 重装出口）、来源切换披露、更新目标 specifier 三条用例。

## 升级说明

- **无破坏性变更、无迁移**。本地路径安装的插件在有更新时点「更新」会把安装源换成 `github:owner/repo`（对话框已披露）；只想看版本不想切源的用户不点更新即可。
