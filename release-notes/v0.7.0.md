# v0.7.0

本版把「IPC 契约、步骤编排、错误文案」三处事实来源全部收敛到单一权威：Rust 结构体经 ts-rs 直出前端类型；就绪时间轴由 Rust detect 推导，前端不再持有步骤列表副本；Rust 命令错误以「key 即英文原文」过 IPC，前端词典是唯一翻译出口。同时修复协议形态安装插件的卡片状态，并补充pnpm 构建脚本审批的自动化修复路径。

## Changes

- **类型契约单一来源**：`LauncherConfig` / `DshStatus` / `MarketCatalog` 等 18 个 IPC 载荷改由 ts-rs 从 Rust serde 结构生成（`src/shared/bindings/`），`types.ts` 只做 re-export 与别名适配；契约漂移从「手改两边」变为 `cargo test export_bindings` 一键再生成
- **就绪时间轴收归 Rust**：新增 `dsh_step_schema` 命令，步骤序列与标题 key 由 Rust 侧统一下发；`DshStatus` 新增 `readyTimeline`，前端不再自行重推导「本地 4 步 / 远程 8 步」的编排
- **错误文案「key 即英文原文」**：Rust 命令 Err 与状态载荷错误字段一律输出本地化前的稳定 key，前端 `tErr()` 经 i18next 查表翻译；zh-CN 词典补齐 150+ 条错误面词条（前端 382 key），词典 miss 落回英文原文，不再静默双语混杂
- **协议形态安装修复**：`github:` / `git+` 等协议形态安装的插件卡片始终显示「未安装」的问题修复——按 spec 前缀+边界字符+目录名双条件匹配落盘条目，命中唯一才采信；`install_receipt` 增加协议形态重装兜底
- **pnpm 构建脚本审批闭环**：插件市场安装被 pnpm 拦截构建脚本时，自动把包名写入 profile 的 `pnpm-workspace.yaml` allowBuilds 并重试，半成品状态可被闭环接管
- **托盘与窗口拆分**：`tray.rs` / `window.rs` 独立成模块，托盘 dsh 三键可用性规则（「空闲且未运行才可启动」）只保留托盘侧一份映射；命令重导出改 `paste!` 宏三件套，删命令只需删一行

## 验证

- `vitest`：67 项全部通过（含协议形态匹配、构建脚本审批、时间轴重置等用例）
- `cargo test`：113 项全部通过（含 ts-rs bindings 生成与 specifier 边界用例）
- `tsc --noEmit`、`pnpm run check:i18n`（前端 382 key，Rust 托盘小表 9 条）无错误、无缺失无死 key
- `pnpm run check:release -- --tag v0.7.0`：版本三处一致、release notes 存在、bundle resources 路径有效
