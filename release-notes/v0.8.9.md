# v0.8.9

本版给 dsh 启动链加了一道启动前导出漂移预检：第三方插件对宿主 `@deepseek-ai/*` 包的具名导入若在宿主实际产物中不存在（v0.8.8 验证栈升线后 `dsh-rewind-plugin` 炸掉整个启动的那类 API 漂移），在启动成功节点的详情里逐行点名，并直接给出「禁用并重试」按钮——不必再等炸一轮后才在启动失败诊断里处理。

## Changes

- **启动前导出漂移预检**：新 `compat` 模块在本地一键启动（spawn/restart 两分支）与远程 8 步时间轴的 start 步骤前，解析 profile 顶层插件对宿主包的具名 import（含 re-export 与 `as` 重命名，过滤子路径与 default 导入），与宿主 main 产物 `export {...}` 聚合清单比对。判定选型：semver peer 失配在 prerelease 宿主生态全是误报（实测 5 包全红且全部能跑），API 导出漂移才是启动必炸的精确信号——实测 22 包扫描唯一命中真雷、零误报，约 100ms
- **披露不拦截**：start 节点 detail 追加失配清单（超 3 条折叠为计数），携带可禁用插件名——前端在启动成功节点上同样渲染「禁用并重试」按钮（复用停用覆盖行写入 + 重跑启动编排，视觉独立于红色失败警示框）；受管授权插件失配时只披露不给按钮（恢复路径是 Repair dsh stack）
- **失败兜底不变**：预检是静态近似（动态 import、default 导入等形态抓不到），漏报场景由既有启动失败诊断兜底，两道闸共用同一禁用动作

## 验证

- `cargo test`：170 项全部通过（含导出漂移回归锚、插件导入抽取、宿主导出解析、披露折叠等新用例；预检链路另有真实环境端到端验证）
- 前端 `vitest`：121 项全部通过（含 done 节点披露渲染、无披露不渲染 2 个新用例）
- `tsc`、`check:i18n`（472 key）、`check:release` 通过

## 升级说明

- **无破坏性变更、无迁移**。启动成功后若 start 节点详情出现 `Incompatible plugin …` 行，即当前装着的插件与宿主存在导出漂移，可点行内按钮禁用重试，或在插件页手动处理
- 终端裸跑 `dsh` 不经过本应用，预检覆盖不到；该场景的失败仍以 dsh 自身的报错输出呈现
