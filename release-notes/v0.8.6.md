# v0.8.6

本版修复插件市场「全部更新只更新一个」的 bug，并把市场更新流程拆成「并发预下载 + 串行安装」两个阶段、更新检测改为并发查询——多插件批量更新不再被单个需要确认的插件卡住，慢网下的下载等待也显著缩短。

## Changes

- **修复「全部更新只更新一个」**：批量更新逐个执行时，只要某个插件的新版本落在 pnpm `minimumReleaseAge` 供应链保护窗口内，原实现就停止批处理，只更新窗口前的插件便遗漏其后所有可更新项。现改为**队列驱动 + 续传**：窗口项与其他项一起进队列，遇之弹知情确认框，用户确认（钉版本安装）或放弃后从队首弹出**继续更新下一个**，直到全部处理完；构建脚本审批挂起同样停留、用户放行后续传。批量绝不因单个需要确认的项而中断抛弃后续
- **更新检测并发化**：`check_updates_once` 由逐包串行查询改为 `std::thread::scope` 并发（每包独立查 registry/GitHub，只读网络不写盘，共享 reqwest Client），已装列表再多检测也不拖长
- **批量更新「并发预下载 + 串行安装」**：串行安装前先把 npm 形态更新包的 tarball 经 `pnpm store add` 并发预热进内容寻址 store（`--dir` 对齐 profile 的 store 上下文），随后 `dsh plugin add` 直接从 store 复用、零下载——下载从「串行累加」降到「最长单包」。GitHub 仓库形态无 registry tarball，照旧串行时下载；预下载只读 store 不写 profile、并发安全，串行安装仍是唯一写盘路径。单个预下载失败容忍，不影响后续串行安装

## 验证

- `cargo test`：164 项全部通过；`cargo clippy` 无警告
- 前端 `vitest` 115 项全部通过（新增「窗口项确认后续传」「窗口项在队尾正确收尾」「放弃窗口项后继续」「GitHub 包不进预下载但仍串行安装」等用例）；`tsc`、`check:i18n` 通过
- 新增后端命令 `market_prefetch`（并发预下载），已注册进 `mod.rs` 与 `main.rs` 的 `invoke_handler`

## 升级说明

- 无破坏性变更、无迁移。批量更新流程从「顺序 for + break」改为「队列驱动 + 续传」及「预下载 + 串行安装」，行为上批量更新更完整、更快；「Update all」按钮在预下载期间显示 Working… 并禁用（防重复点击）
