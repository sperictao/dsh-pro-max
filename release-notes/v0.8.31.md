# v0.8.31

本版让应用从「只适配 dsh web」变成**纳管 DeepSeek Harness 的两种官方形态**：原有的 web 运行档，加上官方的 DeepSeek Harness 桌面应用。设置页新增「纳管形态」两项开关——至少保留一档、可两档并存；未纳管的形态不进界面、也不被触碰。

## Changes

- **纳管形态开关**（设置页 → DeepSeek Harness → 纳管形态）：`managed_surfaces` 持久化「本应用纳管哪些形态」。「至少一档」有两道收口——界面上只剩一档时该档开关置灰（「全关」不可表示），落盘时 Rust 侧再把空值归一化为仅 web。旧配置没有这个字段，按仅 web 处理，无需迁移
- **门禁是完整的**：关掉 web 后，首页 dsh 卡片、插件页的市场四页（发现/收藏/已装/诊断）、模型页、设置页的 dsh 版本 / 开机自启 / 远程授权三节、托盘的 dsh 三键**一起消失**；关掉桌面后，首页桌面卡片与插件页「桌面应用」tab 一起消失。保留插件页视图本身（它承载另一档的 tab）与「纳管形态」节（关掉之后找回开关的唯一入口）
- **桌面应用外部能力**（不依赖桥接、任何桥接态下都可用）：检测安装与版本、检测是否运行、打开/聚焦、请求退出、新版本提示、打开日志目录。打开走应用自己注册的 `dsh://open`；新版本提示读应用自带的 electron-updater 配置再取它的更新源。退出只有 macOS 有入口——Windows 上窗口关闭被应用改成隐藏到托盘、窗口全关也不触发退出，第三方没有可触发的正常退出入口
- **插件页新增「桌面应用」tab**：经**官方的桥接插件**调用桌面应用**自己的** PluginManager / Config Editor，管理它的插件、插件包与运行档配置——不在应用背后直写 `~/.dsh/profiles/desktop`（那会造出第二份插件安装实现，且安装护栏最关键的 `--dump-config` 组合预检对 desktop 档物理不可执行）。决策记录见 `docs/adr/0011`
- **桥接插件是独立仓库、一次性手工安装**：本版发布时同步发布 [dsh-pro-max-bridge](https://github.com/sperictao/dsh-pro-max-bridge)。用户需在官方桌面应用的 Plugins 页粘一次 tgz 地址（已实测该界面接受 tarball URL）；此后本应用能自己管它。桥接未装时界面给出可复制的安装地址与真实原因，而不是笼统的「失败」

## 升级说明

- **无破坏性变更、无迁移**。旧配置没有 `managed_surfaces` 字段，读时按「仅 web」处理，行为与升级前一致
- **桌面形态需要你在官方应用里装一次桥接插件**才会出现它的插件与配置管理；外部能力（检测/打开/退出/更新提示/日志）不需要桥接。安装地址：`https://github.com/sperictao/dsh-pro-max-bridge/releases/latest/download/dsh-pro-max-bridge.tgz`
- **桌面形态只支持 macOS（Apple 芯片）与 Windows（x64）**——官方只发布这两个构建；其余平台上该项开关仍可打开，但界面会说明本平台没有构建
- **两处已知未验证**（不影响本版功能，记录在案）：桌面档的装/卸/启停等**变更**操作未在真机上实装实卸过；在官方应用自己的退出确认框上选「取消」时，我们是否会误报一条失败提示待确认
