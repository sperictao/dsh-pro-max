# v0.3.8

真正恢复 admin capability 下的远程设置页面，并修复新授权插件首次安装后可能破坏 dsh profile 兼容层的问题。

## Fixes

- **远程模型设置仍报 `settings are unavailable in this browser`**：此前 Host 已经用 admin capability 放行 `settings.describe`，但上游浏览器 client 仍按页面 hostname 把所有非 loopback 页面固定为内存 settings mirror，根本不发起远程设置 RPC；authz replacement 现在让既有特权界面尝试 Host-authority RPC，最终权限仍由每个请求经过的 Host fence 与 admin capability 唯一裁决
- **客户端权限判断与服务端事实冲突**：删除“tailnet hostname 等于无管理权限”的第二套客户端事实；没有 admin capability 的远程身份仍返回 403，拥有 admin capability 的身份可以正常读取和编辑远程设置、凭据及其他受保护的 Host 操作
- **插件升级后 dsh 可能立即退出并让 Serve 返回 502**：`dsh plugin add` 会把 Launcher 管理的 `cordis.patch.yml` 兼容条目重置为空；现在插件安装成功后会严格恢复 compat patch，且每次启动带授权插件的 web profile 前再次校验，防止 rc 依赖裂缝导致 attachment/commands 启动崩溃
- **授权插件 pin 更新**：内置 `dsh-client-connection-authz` 更新到 `0.1.0-rc.8-authz.2` / `2fccf0d593b1`，构建时对上游模块 ID 与 loopback initializer 都执行唯一性校验，上游漂移会显式失败
