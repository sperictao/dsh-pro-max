# v0.8.25

本版为 dsh web 加入启动前自愈修复核：宿主升线后 profile 里的陈旧状态（旧时代物化的宿主包影子副本、插件层声明的保留权限预设名）在启动前自动收敛，交给 dsh 自己的机制恢复；观测到保留名冲突导致启动失败时自动修复并重试一次。业务配置格式与后端命令接口均未改变。

## Changes

- **影子副本治理**：web profile node_modules 下的 `@deepseek-ai/*` 真实目录是旧时代 pnpm 物化的 registry 副本，npm dist-tag 的错位让它们永远追不上宿主版本。启动/更新链路现在会在 dsh web 拉起前删除这些真实目录，dsh 的 module-fallback heal 随即以符号链接补回宿主正源副本——版本永远跟随宿主，误删也无损（heal 的 fallback 链接是 symlink，精确区分）；共享层 `~/.dsh/profiles/node_modules` 不越界。
- **保留权限预设剥离**：宿主把 `auto`/`custom` 保留为 permission presets 内置名（构造期校验，配置出现即拒启）。启动前检测生效表（wholesale 覆盖语义下最后声明 `permission` 条目的 bundle 层），若有保留名则在用户层写一条「生效表减保留名」的覆盖行。该行是派生物：冲突消失即自洁删除，bundle 更新后下次启动重算，插件补丁层始终是唯一事实来源。是否剥离由宿主库内容的保留名指纹门控——旧宿主上插件声明 `auto` 预设仍是合法功能。
- **更新链路接入**：更新 dsh、卸载授权插件、安装指定版本三条会在宿主版本变更后重启 web 的链路，重启前必跑修复核（台账进日志，时间轴不展示明细）。
- **冷启自愈重试**：本地一键启动失败且诊断为保留名冲突时，force 修复一轮（越过内容门控——观测到的失败即事实）并重试一次，重试上限 1 防修复-失败循环；时间轴显示「Auto-repairing the dsh profile and retrying…」。本次修复台账（清理了哪些影子副本、剥离了哪些预设）披露在启动 done 明细里。
- **诊断归因增强**：报错最内层是宿主包（如 permission presets 服务）时，反查 profile 里哪个 bundle 层配置了炸掉的条目，把「宿主包条目炸了」映射回肇事第三方插件并保留一键禁用动作；归因失败时照报错误本体并指引查日志，不产出无效的禁用动作。

## 验证

- cargo test 230 用例、clippy `-D warnings`、oxlint、Vitest 236 用例、i18n 词典校验全绿。
- 修复核新增单测覆盖：影子副本删除的 symlink/断链/散文件边界、保留名扫描与剥离（含 `!!js`/Tagged 不可重序列化守卫）、strip 覆盖行的行级增删与空层归一、条目归因反查、诊断分支与自愈重试判据。

## 升级说明

- **无破坏性变更、无迁移**。profile 里的 strip 覆盖行是修复核自动维护的派生数据（带自有标记注释），插件补丁层与共享 node_modules 不受影响。
