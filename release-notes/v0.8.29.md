# v0.8.29

本版修复模型模块添加自定义供应商时报「DSH 拒绝了凭据请求（HTTP 401）」的问题：凭据桥裸发 `/api` 请求不带任何身份，而授权插件不在场时（本地模式明确不依赖它、插件被卸载或装了没加载）dsh 对 `/api` 一律要求本机会话 cookie，裸请求固定 401。现在 Launcher 按与浏览器相同的原生机制——用 dsh 自己打印的 launch token 换会话 cookie——完成鉴权后重试。授权插件在场时行为逐字节不变（不多发任何请求）。业务配置格式与后端命令接口均未改变。

## Changes

- **本机会话（Local Session）**：新增 `dsh/session.rs`——从 `~/.dsh/dsh-web.log` 取当前实例打印的 launch token（即交给浏览器的同一份凭据），经 `GET /?token=<token>` 的 303 换取 `dsh-auth-*` cookie；进程内缓存、不落盘、不绕鉴权，拿不到 token 或换取被拒时按「本机没有可用会话」处理。
- **凭据桥被 401 拒绝才换会话，重试恰好一次**：先用手上已有的 cookie 发请求；被 dsh 以 401 拒绝时换一次会话 cookie 再试，绝不无限重试；重试仍被拒则清掉不作数的缓存，并把残余 401 的原因与下一步（用 DSH Pro Max 重新启动 dsh web 后重试）摆给用户，不再是同一句孤立的 401。
- **修掉既有的 token 截断缺陷**：launch token 是 base64url（32 随机字节 → 43 字符），本地访问地址解析却按字母数字截断，实测 74% 的 token 含 `-`/`_` 会被砍短——浏览器与 Launcher 都会因此换不到 cookie。解析器收敛到 `session.rs` 一处，浏览器地址与会话换取共用。
- **远程一键启动的 verify 步同源修正**：裸 `/` 的 401/404 视为健康应答（与 ready 步同一判据），插件装了但没加载时不再误报「dsh web 没有应答」；本机特权面探测改为「裸请求或本机会话任一可达」，判据是 Launcher 能否以本机身份访问特权 API。
- **`~/.dsh/dsh-web.log` 按 0600 新建**：无授权插件时该日志是本机 launch token 的载体，与凭据文件同一权限基线；已存在的文件不改权限。
- **回归测试**：决策核五例（缓存命中不重取、换会话重试一次、重试被拒不循环且清 cookie、无 token 报残余文案、非 401 原样上抛）、会话换取的字节级测试、单连接 HTTP 桩钉住线上请求形状、带隔离闸门的真机回归（默认 ignore，`DSH_PROBE_PORT`/`DSH_PROBE_TOKEN` + `DSH_PROBE_ISOLATED_HOME` 手动跑）。

## 升级说明

- **无破坏性变更、无迁移**。修复只改 Launcher 侧的请求方式，升级后无需重启已在运行的 dsh web；曾遇到该 401 的环境（未装授权插件、dsh web 由 Launcher 拉起）直接在模型模块重试「添加自定义供应商」即可。dsh web 在外部手工启动且日志里没有 token 行时，本机会话不可得，界面会给出原因与下一步。
