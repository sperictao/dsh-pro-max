# v0.8.8

本版做两件事：把 dsh 验证栈（CLI + 两个内置授权插件）从 `0.1.2` 线整体升到 `0.1.5-alpha.1`，同时放开 dsh 版本安装闸门——任何 dist-tag 指向的版本都可安装，不再因「与内置插件栈不兼容」灰掉安装按钮或遭后端拒绝。

## Changes

- **验证栈升线 0.1.2 → 0.1.5-alpha.1**：`SUPPORTED_DSH_VERSION` 升至 `0.1.5-alpha.1`，内置授权插件同步跟线（`dsh-client-connection-authz` → `0.1.5-alpha.1-authz.1`、`dsh-auth-tailscale` → `0.1.5-alpha.1-auth.1`）。`0.1.5-alpha.1` 现被标记为「验证过的兼容栈」；`0.1.2-rc.1` 等旧线版本标记为「不兼容」
- **0.1.5 Connection 手势 breaking 适配**：0.1.5 新增 `ConnectionFetchHandler.requestBodyMode`（读取请求体前声明 `buffered/streaming` 模式）与 `ConnectionFetchRoute.requestBody` 字段。authz 插件在 `createSharedFetchHandler` 补 `requestBodyMode`、`RegisteredFetchRoute` 补 `requestBody`，对齐上游参考实现
- **放开版本安装闸门**：`dsh_install_version_once` 不再调用 `dsh_version_is_compatible` 拦截跨线版本——任何可解析版本均可安装。前端安装按钮 `disabled` 条件收窄为 `busy`，不兼容行保留红色「与内置插件栈不兼容」警示文案但按钮永远可点；安装 incompatible 版本成功后追加 toast「授权插件可能不兼容，可在启动失败诊断中一键禁用肇事插件」
- **三处 pin 同步**：`mod.rs` 常量 / `build-dsh-plugins.mjs` pin commit / `tauri.conf.json` bundle.resources tgz 文件名（含短哈希），并重建内置插件 tgz

## 验证

- `cargo test`：165 项全部通过
- 前端 `vitest`：119 项全部通过（含「incompatible 行按钮不禁用 + 装完弹风险提示」用例）
- `tsc`、`check:i18n`（472 key）、`check:release` 通过

## 升级说明

- **无破坏性变更、无迁移**。验证栈升线改变「dsh Version」设置页的兼容标记：`0.1.5-alpha.1` 由「不兼容」变为「验证过的兼容栈」，`0.1.2-rc.1` 等旧线版本反向标记为「不兼容」
- 版本安装闸门放开后，跨线版本装完若授权插件失效，走 v0.8.6 已有的启动失败诊断兜底
- 两个 vendored 授权插件仓各有新提交（`021fee6`、`9765f2a`），均已 push 至远端
