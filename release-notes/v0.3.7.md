# v0.3.7

修复远程 capability 未生效时仍被报告为就绪的问题，并补齐授权保存后的重启提示与 tailnet grants 排障指引。

## Fixes

- **远程 capability 被拒仍显示可用**：此前远程验证只检查 HTTPS 与 WebSocket 链路，没有实际探测已配置的 `llm.providers` 与 `settings.describe`；现在会分别验证 use/admin capability，将授权拒绝与端点故障区分开，拒绝时不再报告远程就绪或允许打开远程地址
- **远程授权失败缺少明确去向**：状态页新增 capability 授权被拒提示，指出需要在 tailnet grants 中把已配置的 use/admin capability 授给当前身份到对应 dsh 节点的连接；应用只负责检测与提示，不会自动创建或修改 tailnet grants
- **保存授权后运行态没有更新**：授权区明确提示修改后需要先停止正在运行的 dsh Web，再重新执行“一键启动”，让新的进程环境与 `tailscale serve --accept-app-caps` 同时生效
- **远程访问说明与验证范围同步**：更新设置页和排障文档，说明远程设置与凭据依赖配置的 admin capability，并将验证范围明确为已配置 capability 对应的远程 API
