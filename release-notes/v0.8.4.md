# v0.8.4

本版修复 GitHub 直装插件（`github:` / `git+https:` 落盘形态）永远检不出新版本的缺口：此前更新检测对协议形态 spec 一律不检，且更新动作走的 `name@latest` 对纯 GitHub 插件也不成立。

## Changes

- **git-hosted 插件纳入更新检测**：GitHub 仓库形态（`github_repo_id` 认全形态）已装版本读磁盘事实（node_modules 内 package.json），远端比对 `raw.githubusercontent.com` 默认分支的 manifest（`HEAD` 别名，免先探默认分支名），同一 `is_newer` 语义版本比对，`engines.dsh` 兼容门禁与批量更新照常生效；`file:` 与非 GitHub git 形态维持排除（无远端可比事实）。GitHub 插件卡片此前不显示版本号，现在显示磁盘事实版本
- **更新/重装按原仓执行**：git-hosted 插件的更新与重装不再走 `name@latest`——这类包多半不在 npm registry，`@latest` 要么 404 要么把 git 源覆盖成 registry 包；现统一按 `github:owner/repo` 重装，pnpm 重新解析默认分支 HEAD。npm 形态的 `@latest` 与 minimumReleaseAge 供应链窗口语义不变（git 形态无发布时间，天然不触发该窗口）
- **共享原语收敛**：`githubRepoId` 从市场视图移入 `shared/lib/specifier`（store 更新链路复用，消除 store 反向依赖视图）；npm/git 两路共用的解析失败错误键中性化为 "Cannot parse package manifest"

## 验证

- `cargo test`：164 项全部通过（含 git spec 磁盘版本判定、`file:`/非 GitHub 形态排除等回归用例）；`clippy -D warnings` 干净
- 前端 `vitest`：112 项全部通过（含 `updateSpecifierFor` git 全形态与 npm 语义不回归用例）；`tsc`、`check:i18n` 通过
- 远端端点实测：shadow-mind（0.2.1）、dsh-visualize（0.1.2）、dsh-at-file（0.7.0）三仓库 raw `HEAD` 均 200 且版本可解析

## 升级说明

- 无破坏性变更。已装的 GitHub 直装插件升级后进市场已装页即可看到版本号并接收更新提示
- 语义边界：作者推了 commit 但未升 package.json version 时检不出（版本号即事实源，与 npm 插件一致）；`#ref` 钉住的安装点「更新」会前进到默认分支 HEAD（与 npm 插件「更新即 latest」同语义）；重装 specifier 大小写归一，GitHub 地址大小写不敏感，落盘 spec 形态可能随之规范化
