# v0.3.11

补齐远程授权链上缺失的网络授权环节：异机能连上 dsh 节点 HTTPS 端口，当前必须由
tailnet Access Controls 显式放行 `tcp:443`，App Capability 本身并不会放行端口连接。

## Fixes

- **远程访问「配置了 capability 仍 401/403」或「Tailscale ping 通了但 HTTPS / RPC / WSS
  超时」**：此前说明只聚焦 App Capability 的 `app` grant，忽略了任何异机流量都要先
  经过 tailnet 接入控制这一层。本次把 `"ip": ["tcp:443"]` 确立为所有异机远程访问的
  必需网络授权，并明确它是独立于 `app` 能力授权的另一环
- **修复方式**：文档（CONTEXT.md / dsh-remote-access.md / dsh-remote-access-setup.md）
  与前端集成卡片、中英 i18n、Rust 注释统一更新语义——普通远程访问即使不配
  capability，也需要身份 allowlist + tailnet `tcp:443` grant；配了 capability 时
  `ip` 与 `app` 必须放在匹配同一 `src` / `dst` 的 grant 中
