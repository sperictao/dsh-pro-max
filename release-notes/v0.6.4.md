# v0.6.4

失败路径可观测性专题：三处「失败后不知道发生了什么」的黑盒全部打开。插件安装/更新的 dsh 与 pnpm 子进程输出实时流进市场卡片，失败现场直接留在卡上可重试；dsh Web 启动失败可在时间轴节点就地展开完整日志尾部并复制；插件加载失败的诊断从「日志说了几行」升级为直接点名肇事插件与根因报错，并给出下一步。另将首页状态球尺寸回归源项目默认档。

## Changes

- **安装输出实时流**：新增 `run_capture_lines` 流式捕获（stdout/stderr 各一读线程防堵死锁、stdin 接 null），逐行经 `market-install-log` 事件推进前端——pnpm 进度条 `\r` 刷新拆成独立行，行数封顶 200 防超长安装涨内存，日志区贴底滚动、限高不撑爆卡片。安装、审批放行重跑、更新（name@latest 重装）共用同一通道
- **失败留存卡片**：安装失败不再只有转瞬即逝的 toast——错误信息与已产生的输出明细持久留在卡片失败态，附「重试 / 关闭」操作；specifier 锚定发起卡片，跨安装不错位
- **启动日志直读**：时间轴 start 失败节点新增「查看日志」展开区，新命令 `dsh_web_log` 读取 dsh-web.log 尾部 200 行内嵌展示（每次展开重新拉取，重试后再看是最新现场），可一键复制；日志缺失/为空显示占位文案
- **插件失败点名**：启动失败诊断优先解析日志尾的 loader 链（`loader entry` 可多层嵌套，最内层非 `cordis:` 节点即肇事插件；链上全为内置节点时从根因引号取缺失模块名），以「插件树加载失败」/「fatal load failure」致命标记门控——软失败告警与 probe warn 不误判。诊断文案直接点名插件包名与根因报错，方案指明插件页移除/更新、「修复 dsh 兼容栈」恢复受管授权插件
- **状态球回归默认档**：球 170px / 图标 88px / 状态文字 24px（对齐 codex-pro-max 源项目默认尺寸，v0.6.3 曾取紧凑档 124px）
