# v0.8.16

API Key Credential Lifecycle 完整收口版：在 v0.8.15 的 DSH Credential Plane 基础上，补齐 Provider 删除时的 managed credential 清理语义，并完成新增、保留、覆盖、热更新、删除与环境变量优先级的端到端验收。

## Changes

- **删除 Provider 时清理自有 managed credential**：当 Provider 的 `apiKeyEnv` 正好等于页面按 route 派生的 `<ROUTE>_API_KEY`，且该 credential 已配置、来源可写时，先执行 `model_credential_unset`，再删除 Provider settings
- **避免误删共享凭据**：custom/shared credential reference 不做清理；继承自启动环境变量的只读 credential 也不会被应用删除或覆盖
- **失败可重试**：credential cleanup 失败时 Provider 仍保留在界面与配置中，用户可以直接重试删除；cleanup 成功后再提交 settings，两个阶段均保持幂等
- **完整 credential 生命周期验收**：覆盖 managed credential 的 set → replace → unset，以及修改 managed credential 后下一次 resolver/Test/Fetch 即生效、无需重启
- **write-only API Key 保留语义**：编辑现有 Provider 时 API Key 输入保持空白；空白保存不会重写 secret，也不会改变现有 credential reference
- **新增 Provider secret 隔离**：新增 API Key 只通过 `model_credential_set` 写入 credential store，`settings.yaml` 仅保存 `apiKeyEnv` 引用，明文 secret 不进入 Provider settings
- **解析优先级持续对齐 DSH**：继承的进程环境变量保持最高优先级且只读；managed credential 移除后按规则回退到项目 `.env` 与用户 `~/.dsh/.env`
- **Add / Remove Provider UI Audit 扩展**：现有浏览器审计直接验证 credential write/unset 与 settings 保存顺序，不新增重复测试流程
- **E2E smoke 契约同步**：主 smoke mock 补齐 `model_credential_unset`，确保 Provider 删除闭环与真实 credential 生命周期一致

## 升级说明

- 不需要迁移现有 Provider 配置；`settings.yaml` 仍只保存 credential reference，不保存明文 API Key
- 删除使用默认派生 `<ROUTE>_API_KEY` 的 Provider 时，应用现在会同时移除其可写 managed credential，避免 credential store 留下孤儿 secret
- custom/shared credential reference 不会随 Provider 删除；启动环境变量来源始终视为只读并保留
- 编辑 Provider 时留空 API Key 仍表示“保留现有凭据”；只有输入新 key 时才覆盖同一 credential reference
- managed credential 的修改与删除会在下一次 Test / Fetch 中直接体现，无需重启应用
