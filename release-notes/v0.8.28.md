# v0.8.28

本版修复插件市场把 github 形态插件的「更新」误判成「安装未生效」的问题：这类插件的更新就是同键重装，pnpm 解析回同一 commit 时 profile 的 `package.json` 逐字节不变，而安装护栏的落盘校验只按「依赖集合是否变化」判定，于是更新成功也照报假失败（实测 `@dsh-external/dsh-auto-review-jev`：`dsh plugin add` 退出码 0，锁文件与 `node_modules` 均已重写，界面仍报「web profile 中没有任何落点」）。现在护栏同时认「落点已在盘上」这一事实。业务配置格式与后端命令接口均未改变。

## Changes

- **落盘校验认「落点已存在」**：协议形态（`github:` 等）的落盘键名无法从 specifier 预知，除「依赖集合变化」（新键落盘，或既有 spec 被改写）外，after 态已存在同一仓库的落点也算生效——仓库标识经 `github_repo_id` 归一，pnpm 把 `github:owner/repo` 落盘成 `git+https://github.com/owner/repo.git` 的形态同样命中，与安装回执、更新检测共用同一份归一语义。首次安装被 pnpm 静默拦下（B8 本要拦的假成功）仍照旧报「未生效」，护栏不放宽。
- **护栏层快照带上落盘 spec**：`ProfileLayer.dependencies` 由键名列表改为「键 → 落盘 spec 原文」，一次读盘同时支撑重装判定与既有的重复挂载剥离、回滚对账，不留第二份事实。
- **回归测试**：新增断言固定真机事实——同键重装逐字节不变仍判生效、pnpm 规范化形态命中落点、spec 被改写（升级到新 ref）生效、落点不存在且集合未变仍判未生效、仓库不同不算落点。
- **术语同步**：`CONTEXT.md` 的「安装护栏」条目写明两种形态的落盘校验规则。
