# v0.8.11

本版补齐模型模块三项能力：基于 models.dev 全量目录的模糊搜索联想（自动更新）、按供应商拉取上游模型列表（兼连通性验证）、以及 settings.yaml 的原子写入。

## Changes

- **模型目录模糊联想**：内置 models.dev 全量模型目录（4000+ 条，与 CCursor 同源），投影为 `{id, name, family}` 本地快照；进入模型页立即可用，快照缺失或超过 24h 自动后台刷新，刷新失败静默降级（已配置模型仍可联想）。搜索交互与插件市场一致（`toLowerCase` 子串实时匹配 id 与名称），候选按供应商 wire 协议过滤家族并截断 50 条，支持键盘上下/回车/Esc/点击外部关闭。落点两处：默认模型输入框、每个供应商卡的「添加模型」。顺带修复了模型输入框 datalist 引用不存在导致联想失效的旧问题
- **上游模型列表拉取**：供应商卡片新增「拉取模型列表」——按 wire 协议请求上游模型列表（openai 系 `/models`、anthropic `/v1/models` + 版本头，10s 超时），结果逐条点选追加（去重，已添加标记 ✓）。密钥经环境变量名解析、只在内存中，任何路径不落盘不进日志；环境变量未设置 / 网络失败 / HTTP 错误分别给出静态中文错误文案（URL、状态码进日志）。这也是配置正确性的连通性验证手段
- **settings.yaml 原子写**：保存改为临时文件 + fsync + rename，写入中断电/崩溃不再产生截断的 settings.yaml
- **内务**：收录 Comet 项目配置（`.comet/config.yaml`，对应 `.gitignore` 反忽略规则的既定意图）

## 验证

- `cargo test`：179 项全部通过（目录投影 family 映射/去重/坏条目、快照往返与损坏容忍、URL 拼接、响应解析、env 缺失分支、原子写无 tmp 残留）；`cargo clippy -- -D warnings` 通过
- 前端 `vitest` 127 项、`tsc`、`check:i18n`（488 key，新增文案 zh+en）、`e2e smoke` 全部通过
- 独立复核两轮：修复 `model_remote_list` IPC 参数名与 Tauri camelCase 取参不一致的真实链路缺陷（baseURL → baseUrl）

- 无迁移、无配置变更
- 「拉取模型列表」要求 dsh-pro-max 的启动环境中已设置对应 API Key 环境变量（与 dsh 运行时同一变量名）；未设置时会有明确提示，不影响其余功能
