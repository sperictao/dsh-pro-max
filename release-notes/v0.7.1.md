# v0.7.1

本版补齐插件更新链路的最后一公里：更新检测的「当前版本」改读磁盘事实，latest 落在 pnpm minimumReleaseAge 供应链保护窗口内时先弹知情确认框再钉版本重装，杜绝「更新成功」实为静默回旧版的假成功。同时修复强杀 dsh 后孤儿写锁导致的启动假故障，状态球视觉升级为光晕双层化与图标呼吸变色。

## Changes

- **供应链窗口知情更新**：更新检测经完整 packument 判定 latest 发布时间，落在 pnpm minimumReleaseAge 保护窗口（内置默认 24h）内时标记 `latestInReleaseAgeWindow` 并透传 `latestPublishTime`；窗口内 `@latest` 会被 pnpm 静默解析回旧版且退出码仍为 0（假成功），现改为先弹供应链确认框（展示版本过渡与发布时长），知情确认后才以钉版本重装并自动写 `minimumReleaseAgeExclude`
- **构建审批对话框加固**：Esc 等价取消、焦点默认落取消键（安全默认）、放行重试期间禁撤、框内预告知取消去向；两个决策对话框的取消键改为明确动作文案（「保留当前版本」「保持脚本拦截」）
- **孤儿 credentials 写锁自愈**：dsh_stop 强杀可能把 `~/.dsh/.credentials.yaml.lock` 孤儿化（dsh 自身不回收），此后每次启动都在锁等待上超时崩溃——Launcher 在启动前与强杀停止后按「持锁 PID 已死」判定自动清理，活锁（真实并发）不动；启动失败诊断对锁超时指纹优先于插件链归因，解法指向锁文件本身
- **更新检测读磁盘事实**：当前版本优先读 profile `node_modules/<name>/package.json` 的实际 version，范围 spec（`^ ~`）即靠它参与检测，磁盘不可得回退 spec 精确版本；协议形态恒不检
- **状态球视觉升级**：光晕双层化（近距 36px 清晰晕 + 远距 44px 柔光）并整体放大；图标颜色随呼吸明暗变化（谷点染状态浅色调、峰点纯白），与缩放同一条动画严格同拍同相位

## 升级说明

- 无配置与数据迁移；v0.7.0 用户可直接升级
- 更新行为变化：窗口内的新版会先弹确认框（默认取消），确认后才真实更新——这是有意的供应链保护，不是故障
