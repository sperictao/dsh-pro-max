# v0.8.22

本版做三件事：把 dsh 验证栈整体升到 `0.1.6-alpha.1`；把 Rust 侧所有用户可见文案改成「模板 key + 参数」过 IPC，让中文界面下的诊断不再显示英文；顺带修掉一个约 1/5 概率复现的启动进度偶发失败。

## Changes

- **验证栈升线 0.1.5-alpha.1 → 0.1.6-alpha.1**：`SUPPORTED_DSH_VERSION` 升至 `0.1.6-alpha.1`，内置授权插件同步跟线（`dsh-client-connection-authz` → `0.1.6-alpha.1-authz.1`、`dsh-auth-tailscale` → `0.1.6-alpha.1-auth.1`）。三处 pin（`mod.rs` 常量 / `build-dsh-plugins.mjs` pin commit / `tauri.conf.json` bundle.resources tgz 文件名）与 submodule 指针已同步，插件 tgz 与 sha256 已重建。上游 host 侧 Connection API 本次未变，两个插件源码零改动
- **诊断文案双语化（本版主体）**：此前 Rust 先把值插进句子再把成品发过 IPC，成品句子永远命不中词典里带 `{{name}}` 的模板 key——73 条早已写好的译文从未生效，中文界面下带值的诊断（含绝大多数启动失败原因）恒为英文。现在契约是 `Message { key, args }`：key 是英文原文、args 是插值数据，后端绝不插值；前端是唯一解析点，命中词典用译文插值、未命中就用同一组参数就地填出英文原文（不会露出 `{{name}}`）。参数可嵌套，内层同样走词典
- **文案归属按渲染点划分**：前端渲染的走词典（`Message`）；交给系统 API 的（托盘菜单、系统通知标题）没有前端渲染点，走新增的 `i18n::trf` + 小表。系统通知标题原先恒为英文，本次一并修正
- **时间轴 `detail` 改为行列表**：由「基线文案 + 拼接披露行」改为 `Vec<Message>`，每行独立本地化；拼接会把多个词典 key 压成一句成品英文
- **凭据写锁等待对齐宿主**：`DOCUMENT_LOCK_WAIT_MS` 为凭据文档留了 30s，而 Launcher 沿用 `dsh-atomic-write` 的通用默认 2s——dsh 正在启动或写记录时，Launcher 自己的写入会被误判成超时。现已对齐 30s，锁协议其余部分未动
- **修复启动进度偶发失败**：选完服务后的「自动交焦」用的是 `setTimeout(..., 0)`，实测会晚 11–78ms 才跑；这期间若焦点已被用户（或自动化）移走，正在输入的字符会被送进另一个字段且没有任何提示。现在交焦可取消，并在落地前复查焦点，用户自己找到了下一个字段就放弃这次交焦
- **lint 闸门归零**：本地 `pnpm run lint` 此前会扫到 agent CLI 的本地目录并判红 21 个 error（CI 干净检出上不存在这些目录）；现按 `.gitignore` 排除，并把 lint 范围收窄到与 `tsc`/`vitest`/CI 一致的仓库自有代码

## 验证

- `cargo check --all-targets` 0 错 0 警；`cargo clippy --all-targets -- -D warnings` 干净；`cargo test` 216 项全部通过
- 前端 `tsc` 0 错；`oxlint` 0 错 0 警；`vitest` 40 文件 236 项全部通过
- `check:i18n` 通过（622 key，无缺失、无死 key）——校验脚本新增「Rust 消息字面量 ⊆ 词典」与「词典无死条目」两侧，与既有的 `t()` ⊆ 词典、`tr/trf` ⊆ 托盘表合成四向校验；本次改造前那条「73 条模板不可达」的警告随之消失
- `check:release` 通过；`cargo test` 后生成物与 `Cargo.lock` 稳定（CI 的 generated-artifacts 守卫）
- `e2e` 冒烟 13 步通过，交焦修复后连跑 5 次全过（修复前基线约 1/5 失败）
- 实机跑通：把两个插件 tgz 装进临时 `DSH_HOME` 的 web profile，pnpm 解出的 peer 全落在 `0.1.6-alpha.1` 线上；`--dump-config` 显示内置 `connection` 行按 name 守卫精确 disabled、两个替代行正确插入；真启动 web 服务后，Host 伪造返回 403，浏览器收到的模块表已用替换包取代内置 `client.js`

- 诊断文案现在随界面语言解析，之前只有固定文案能翻译、带值的句子恒为英文；语言切换仍不回溯重翻已显示的消息（与既有语义一致）
