# v0.8.1

本版修复协议形态（`github:`）插件安装后的已装状态匹配：pnpm 会把无 fragment 的 `github:owner/repo` 落盘规范化为 `git+https://github.com/owner/repo.git`，旧的前缀判定认不出这个形态，装成功的插件在发现页与收藏页恒显「未安装」（dsh-at-file 即此因），重装回执也恒为空。

## Changes

- **协议形态已装匹配按仓库标识归一**：新增 `githubRepoId` 归一（`github:owner/repo`、`git+https://github.com/owner/repo.git`、`git+ssh`/`ssh`/`git@` 六种 GitHub 形态统一提取 `owner/repo` 并折叠大小写，`#fragment` 与 `.git` 后缀剥离），前端卡片匹配与 Rust 安装回执定位同一套语义，由 `specifier_cases.json` 新增的 `githubRepoId` 向量组两侧共同驱动；匹配从「spec 是 specifier 前缀」改为「双方仓库标识等值 + 目录名双条件」，唯一命中才采信（0 或 ≥2 → 如实不猜）
- **兄弟仓精确命中**：等值比较消灭了前缀族的边界特判——`owner/dsh` 与 `owner/dsh-relay` 同时在装时，旧语义因前缀歧义对两者全部拒绝（卡片都不显示已装），新语义各自精确命中
- **归一只用于匹配**：落盘 spec 原样展示，不碰 pnpm 事实；npm 形态卡走包名精确表不受影响，非 GitHub 协议形态（`file:`、`npm:`）归一返回 null 行为不变
