# v0.6.6

修复首页「一键启动 / 一键重启 dsh web」后启动进度不跟随的问题：点击后时间轴先整体翻回待执行、再随后端事件逐节点点亮，进行中状态与按钮文案同步锁定。同时插件市场已装页新增「重新安装」入口，覆盖终端手动安装被拦构建脚本留下的半成品。

## Changes

- **启动进度实时跟随**：一键启动/重启时，时间轴先整体翻回待执行（○），再随后端 `dsh-step` 事件逐节点点亮（进行中 → 完成）；修复此前「点击后节点不跟随、残留上次就绪状态」的问题
- **托盘回声不再顶掉进度显示**：`dshHasRunSetup` 置位上移到 busy 守卫之前，托盘点击经广播回到同窗口被守卫挡下时，时间轴仍以事件流为准；`handleDshStep` 收到首个 running 事件时兜底置位，双保险
- **重启失败复位**：一键重启在停止阶段失败时回到状态驱动视图，不留半吊子的全待执行时间轴
- **市场已装页新增「重新安装」**：无更新时提供与「更新」同一通道（`name@latest` 重跑安装）的重装入口，覆盖终端手动 `dsh plugin add` 被 pnpm 拦截构建脚本留下的半成品；与「更新」所在分支互斥不共存
- **i18n**：补齐「重新安装 / 已暂停：请先放行构建脚本」等词条（前端 237 key）

## 验证

- `vitest`：64 项全部通过（新增「fresh start 重置骨架为全 pending」「托盘回声置位且不重置时间轴」「handleDshStep running 兜底置位」等用例）
- `tsc --noEmit`、`pnpm run check:i18n`（前端 237 key）无错误、无缺失无死 key
- 一键重启经真实 dev 实例 + 辅助功能树抓帧实测：进行中状态球「处理中…」、按钮「重启中…」、时间轴 8 节点整体翻回 ○ 后逐节点点亮
- `pnpm run check:release -- --tag v0.6.6`：版本三处一致、release notes 存在、bundle resources 路径有效
- 本版未改动 Rust 代码
