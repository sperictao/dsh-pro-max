# v0.8.30

本版把 dsh 验证栈整体升到 `0.1.7-alpha.1`，并把模型配置的落盘位置迁到 0.1.7 的新事实来源：设置不再写 `~/.dsh/settings.yaml`，而是写 web profile 补丁层（`~/.dsh/profiles/web/cordis.patch.yml`）里 `agent-default-model` 与 `llm-pi-ai` 两条目的 `config`。0.1.7 改了 Connection 契约（新增 `operator`/`admit`、handler 多一个 `peer` 参数、结果可携带二进制附件），两个内置授权插件同步跟线重做；远程模式新增一条在 Tailscale Serve 层拦下 dsh 文件打开路由的守卫。业务界面与 IPC 命令接口未变。

## Changes

- **验证栈升线 0.1.6-alpha.1 → 0.1.7-alpha.1**：`SUPPORTED_DSH_VERSION` 升线，两个内置授权插件同步跟线（`dsh-client-connection-authz` → `0.1.7-alpha.1-authz.1`、`dsh-auth-tailscale` → `0.1.7-alpha.1-auth.1`）。三处 pin（`mod.rs` 常量 / `build-dsh-plugins.mjs` 的 pin commit / `tauri.conf.json` 的 bundle.resources tgz 名）与 submodule 指针已同步，插件 tgz 与 sha256 已重建。
- **连接替换插件按 0.1.7 契约重做**：`HostConnectionHandle` 新增 `operator`（直接复用上游 `OperatorPeer`，不再自写一份）与 `admit`；RPC handler 收到第 4 个参数 `peer`；带附件的处理结果以 `multipart/form-data` 返回（分片名 `bytes-<index>`，`metadata` 分片携带扩展信封与 `{path,codec,part}` 映射）。浏览器半边仍取自官方产物加两处字符串替换，构建脚本的唯一性锚点在 0.1.7 产物里各命中一次。
- **特权端点判定改为两级**：混合命名空间仍按精确端点，整个命名空间都不存在 use-authority 方法的按前缀判定。0.1.7 把终端控制器扩到十个方法（`create`/`write`/`resize`/`close` 等，以系统用户权限开真实 PTY），只维护精确端点名会静默失败开放；本次补入 `terminal`、`workspace`、`workspaceFiles`、`account`、`officeToPdf`、`cordisHostRunner` 等命名空间。
- **模型配置域迁移到 profile 补丁**：保存只替换本域两行的 `config` 块，行内其它键（`disabled` 等）、其它行、注释与 `!!js` 表达式逐字节保留；撤掉 config 后只剩 id/name 的空壳行整行删除；内容未变时免写盘。默认模型 provider/model 缺任一即撤掉该行 config，提供商列表为空即撤掉 `llm-pi-ai` 行的 config（缺省＝未设置，与 dsh schema「空 dict 与缺席等价」一致）。
- **远程模式新增 `/open-in-app` 前缀守卫**：dsh 0.1.7 的 open-in-app 宿主插件在 `/api` 之外注册了应用目录、图标与 `POST /open-in-app/open`（在宿主机启动应用）三条路由。它自己会问 `connection.requestRejection`，但那个 seam 只按 `trusted-host` 档裁决，与普通 API 同档。Launcher 的策略是「在本机启动应用只能是本机操作」，因此在 Serve 层按 mount 拦下整条前缀（先挂守卫、再挂根路由，顺序即 fail-closed），第 8 步验证会实际探测该前缀必须返回守卫文案，探到 dsh 的应答即判定失败并保持远程不可用。
- **模型目录改用合并目录**：取 models.dev `catalog.json?type=all`，wire 协议家族读服务商自己的声明而不是模型 id 的归属（Claude 模型不再因被 OpenAI 兼容网关发布而丢失 anthropic 归属）；绑定版本后的目录快照与界面投影随之更新。
- **文档与测试同步**：`CONTEXT.md` 的模型配置与远程暴露面两条语义边界按新事实重写，`docs/dsh-remote-access-setup.md` 补上守卫的手动配置与验证方式，模型模块规格、生成物注释与相关测试一并更新。

## 验证

- cargo test 252 用例全绿（3 ignored）；`cargo clippy --all-targets -- -D warnings` 0 warning；版本号四处（package.json / tauri.conf.json / Cargo.toml / Cargo.lock）一致。
- oxlint 0 错 0 警；`tsc --noEmit` 干净；Vitest 253 用例全绿；i18n 校验通过（前端 635 key、托盘 9 条，无缺失无死 key）；e2e 冒烟全过。
- **真实 dsh 0.1.7-alpha.1（隔离 `DSH_HOME`，非打桩）**：两个插件 tgz 装入 web profile 后 `--dump-config` 显示内置 `connection` 行按 id+name 精确 disabled、两条替代行正确插入；`GET /` 与 `POST /api/session/list` 均 200，说明新契约下插件加载与 RPC 派发正常。
- **模型域落到 dsh 自身可读**：按本版写入器产出的行格式写入两行后启动，`settings/describe` 立即报出 provider/model/reasoningEffort 与凭据引用，`namespaces` 里 `agent-default-model`、`llm-pi-ai` 命中；补丁被外部改写后 dsh 热重载，无需重启。
- **远程暴露面实测**：以 `--trusted-host` 加 Tailscale 身份头与 App Capability（JSON 对象）模拟远程身份，use 档 `GET /open-in-app/apps` 200、`POST /open-in-app/open` 带合法请求体返回 `{"ok":true}`，同身份打 `settings/describe` 403——守卫的必要性由此确证，而不是按「无鉴权」的猜测加入。
- **凭据文件契约核实**：`dsh-credentials-local`（0.1.6 与 0.1.7 同一行为）要求凭据文件权限 0600、且拒收预发布扁平布局（要求 `version: 1` 并把条目嵌到 `refs:` 下）；Launcher 写 v1 且以 0600 新建，合规。
- **待真机复核**：Serve 层守卫未在真实 tailnet 上执行过（其语义由 Tailscale 源码与 CLI 帮助确认），交互层改动按仓库规则需在 `pnpm tauri dev` 上点过关键路径才算完成。

## 升级说明

- **dsh 会被重装到 0.1.7-alpha.1**：一键启动与自启按锁定版本装回；跨线旧版（含 0.1.6 线）标记不兼容并走修复流程。
- **模型配置无需手工迁移**：`~/.dsh/settings.yaml` 由 dsh 0.1.7 首次启动时一次性导入（导入前改名 `settings.yaml.imported`），Launcher 之后直接写 profile 补丁；导入结果与界面显示一致。
- **远程模式**：重新一键启动会挂上 `/open-in-app` 拦截；按文档手工配置过 Serve 的部署，请照 `docs/dsh-remote-access-setup.md` 补上那条 `--set-path=/open-in-app` 的 `text:` 挂载。
- **已知边界**：`dsh.bundle.patch` 若被插件声明为多文件列表（0.1.7 新支持的形态，现行生态仍用单文件声明），Launcher 的护栏与修复路径会回退到默认的 `cordis.patch.yml`。本版不为尚不存在的使用方做投机适配，待有插件实际采用时再跟。
- **排障**：若 dsh 因凭据文件拒绝启动，按日志提示处理——权限不足则改 0600；旧扁平布局则补 `version: 1` 并把条目嵌到 `refs:` 下（Launcher 读得懂扁平形态，但 dsh 自身会拒启）。
