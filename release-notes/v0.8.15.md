# v0.8.15

DSH Credential Plane 正式切换版：将 Models 的 API Key 从“环境变量名配置”升级为与 DeepSeek Harness 一致的凭据生命周期，同时保持 secret 单向、write-only，不进入 `settings.yaml`、React 持久状态或可读 IPC。

## Changes

- **DSH Credential backend**：新增 `model_credential_describe / set / unset`，运行中的 DSH 优先通过官方 credential RPC；离线模式读写 `~/.dsh/.credentials.yaml`
- **凭据解析优先级对齐 DSH**：继承的进程环境变量 → `~/.dsh/.credentials.yaml` → 当前工作目录 `.env` → `~/.dsh/.env`；环境变量来源保持最高优先级且不可由应用覆盖
- **安全写盘**：离线 credential store 使用锁、临时文件与原子替换；POSIX 下检查 owner-only 权限，Windows 使用 replace-existing 原子替换语义；兼容旧 flat prerelease credential 布局并在写入时升级
- **API Key 改为 write-only UI**：ProviderDialog 不再暴露 `API Key Env Var`，改为密码型 `API Key` 输入；编辑现有 Provider 时不会回填或读取 secret
- **引用与 secret 分离**：`ProviderConfig.apiKeyEnv` 继续只保存 credential reference；新增 Provider 输入 key 时按 DSH 规则派生 `<ROUTE>_API_KEY`，明文 key 单独写入 credential store
- **Test / Fetch 支持未保存 Key**：用户正在输入的 API Key 可直接用于 Test connection 和 Fetch list，无需先保存；临时 key 不进入持久模型缓存 identity，也不会污染已保存凭据的缓存
- **Ready 状态切换到 credential describe**：Models 不再依赖 Launcher 进程的旧 `model_env_status`；Provider readiness 由 DSH credential plane 的 `configured` 状态决定
- **保存与重试语义**：Provider 配置先提交、credential 后写入；credential 写入失败时保留 Dialog，重试只执行未完成的 credential 阶段，避免重复保存已经成功的配置
- **默认模型落盘时机修正**：首个 Provider 的 key 成功存储并真正 Ready 后，才在后续配置写入中 materialize default model
- **Transient Fetch readiness 修复**：修复“自动模型发现已经使用临时 API Key 成功，但手动 Fetch list 仍保持 disabled”的状态分叉；ProviderDialog 现在直接使用 discovery 的 `canReload` 作为唯一 credential-aware readiness 来源
- **UI Audit 契约同步**：Models 的正式浏览器 capture 全部迁移到 write-only API Key / credential describe 语义，并保留 Test、Fetch、Save retry、Provider 卡片操作等回归门禁

## 升级说明

- 现有 Provider 配置保持兼容；`settings.yaml` 中仍只保存 `apiKeyEnv` 引用，不保存明文 API Key
- 新增或更新的 API Key 默认写入 `~/.dsh/.credentials.yaml`；应用不会提供读取 secret 的 IPC
- 已存在的进程环境变量优先级最高且视为只读；如果修改的是启动环境变量，需要重启对应进程后才会生效
- managed credential file 的修改会在下一次 Test / Fetch 请求中直接生效，无需重启应用
- 编辑 Provider 时 API Key 输入框保持空白表示“保留现有凭据”；只有实际输入新 key 时才覆盖同一 credential reference
